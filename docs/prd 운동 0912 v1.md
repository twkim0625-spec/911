## 1. 개요
- **한 줄 정의:** 운동을 처음 시작하는 초보자를 위해, 온보딩 설문 응답을 바탕으로 개인 맞춤 운동을 추천해 주는 모바일 앱
- **해결하는 문제:** 운동을 시작하고 싶지만 무엇을, 어떻게 해야 할지 몰라 시작을 미루거나 잘못된 운동으로 부상 위험에 노출되는 문제
- **타깃 사용자:** 운동 경험이 거의 없는 초보자. 목표·경험 수준·보유 기구/장소·부상 이력·가능 시간이 사람마다 달라 일반화된 루틴으로는 만족하기 어려운 사용자
- **플랫폼:** 모바일 앱 (iOS + Android)

## 3. 목표 (Goals)
- 운동 초보자가 스스로 운동을 고민할 필요 없이, 설문 응답만으로 자신에게 맞는 운동을 추천받게 한다.
- 부상·제약이 있는 사용자에게 안전하지 않은 운동이 추천되지 않도록 한다.
- 온보딩부터 첫 추천 확인까지의 과정을 짧고 간단하게 만들어 이탈을 최소화한다.

## 4. User Scenarios   ← 사용자 인터뷰
### Scenario 1 — 첫 방문 온보딩과 첫 추천 받기
- **사용자:** 운동을 처음 시작하는 초보자
- **상황:** 앱을 처음 설치하고 실행함
- **목표:** 나에게 맞는 운동이 무엇인지 알고 싶음
- **흐름:** 앱 실행 → 온보딩 설문(목표·경험·보유 기구/장소·부상 이력·가능 시간) 응답 → 추천 결과 확인
- **완료 조건:** 사용자가 자신에게 맞춰진 운동 목록(각 운동에 대한 설명 포함)을 화면에서 확인한다

### Scenario 2 — 기구 없이 집에서 운동하기
- **사용자:** 헬스장 기구가 없는 초보자
- **상황:** 온보딩 설문에서 "보유 기구 없음"으로 응답함
- **목표:** 맨몸으로 할 수 있는 운동을 추천받고 싶음
- **흐름:** 온보딩에서 기구 없음 선택 → 추천 요청 → 맨몸 운동 위주 결과 확인
- **완료 조건:** 추천 목록에 기구가 필요한 운동이 포함되지 않는다

### Scenario 3 — 마음에 안 드는 추천 다시 받기
- **사용자:** 기존 이용자
- **상황:** 추천받은 운동 중 하기 싫거나 수행 불가능한 운동이 있음
- **목표:** 대체 운동을 받고 싶음
- **흐름:** 추천 화면에서 특정 운동에 "다른 운동 추천" 선택 → 대체 운동 확인
- **완료 조건:** 기존 운동을 대체하는 새 운동이 표시된다

## 6. Success Criteria
- SC-001: 신규 사용자가 온보딩 설문을 시작해 첫 운동 추천 결과를 확인하기까지 3분 이내에 완료한다. (⚠️ 가설 — 실측 검증 필요, 오픈 이슈 참조)
- SC-002: 부상·제한사항을 입력한 사용자에게 해당 부위에 부담되는 운동이 추천되는 사례가 0건이다.
- SC-003: 보유 기구 없음으로 응답한 사용자의 추천 목록에 기구 필요 운동이 포함되는 사례가 0건이다.

## 7. Edge Cases
- 온보딩 설문을 끝까지 마치지 않고 이탈한 경우: 추천을 위한 최소 필수 항목(목표, 기구 보유 여부)이 없으면 추천을 진행하지 않고 재입력을 안내한다.
- 설문 응답이 서로 모순되는 경우(예: 부상 부위를 포함하는 운동을 선호로 선택): 안전 제약(FR-005)이 선호보다 항상 우선한다.
- 제약 조합이 극단적이어서 추천 가능한 운동이 거의 없는 경우(예: 다부위 부상 + 기구 없음): 스트레칭 등 안전한 최소 대체 운동만 추천하거나, 추천이 제한적임을 안내한다.
- 네트워크/서버 오류로 추천을 받지 못하는 경우: 오류 상태와 재시도 옵션을 보여준다.
- 설문을 전혀 하지 않은 상태로 추천 화면에 접근하는 경우: 추천을 위해 최소 정보 입력이 필요하다는 안내로 온보딩을 유도한다.
- 중복 설문 제출(같은 세션에서 설문을 여러 번 제출): 마지막 제출 값만 유효한 응답으로 반영한다.

## 11. Assumptions
- 온보딩 설문의 최소 항목은 목표, 운동 경험 수준, 보유 기구/장소, 부상·제한사항, 가능 시간으로 가정한다.
- 추천 로직은 v1에서 설문 응답 → 매칭 규칙 기반(룰 베이스)으로 시작하며, 웨어러블 데이터 연동이나 ML 기반 고도화는 v1 이후로 가정한다.
- 운동 콘텐츠(이름, 설명, 수행 방법, 부위, 난이도, 기구 요구사항)는 사전에 구축된 운동 데이터베이스에서 제공된다고 가정한다. 데이터베이스의 출처(자체 제작 vs 외부 라이선스/API)는 미정.
- 서비스 이름·브랜드 톤·시각 디자인은 아직 확정되지 않았으며, 별도 brand-voice·design-brandfit 단계에서 정해진다고 가정한다.
