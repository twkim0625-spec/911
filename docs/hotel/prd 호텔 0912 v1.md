## 1. 개요
- **한 줄 정의:** 어떤 도시로 여행을 가든, 사용자의 예산·일정·선호를 바탕으로 그 도시에서 묵을 호텔을 추천해 주는 모바일 앱
- **해결하는 문제:** 처음 가보는 도시에서는 지역 정보가 없어 예산과 취향에 맞는 호텔을 고르기 어렵고, 수많은 리뷰/평점을 일일이 비교하는 데 시간이 든다
- **타깃 사용자:** 그 도시에 처음 가보는 일반 여행객
- **플랫폼:** 모바일 앱 (iOS + Android)

## 2. 배경 & 근거
- **시장/경쟁 맥락:** ⚠️ (benchmark.md 없음 — 추후 보완. benchmark-research 스킬로 OTA(부킹닷컴·아고다·야놀자 등) 및 기존 호텔 추천/큐레이션 서비스와의 비교가 필요하다.)
- **우리의 차별 프레이밍:** ⚠️ (benchmark.md 없음 — 추후 보완. 현재는 "예산·일정·선호 입력 + 기존 리뷰·평점 데이터 분석 기반 추천"이라는 인터뷰상의 방향성만 있고, OTA의 단순 필터·정렬 대비 구체적 차별점은 검증되지 않음.)

## 3. 목표 (Goals)
- 처음 가보는 도시에서도 사용자가 별도로 지역을 조사하지 않고 예산·일정·선호 입력만으로 적합한 호텔을 추천받게 한다.
- 리뷰/평점 데이터를 사용자 대신 종합·요약해 비교 부담을 줄인다.
- 도시 입력부터 추천 확인까지의 과정을 짧게 만들어 이탈을 최소화한다.

## 4. User Scenarios   ← 사용자 인터뷰
### Scenario 1 — 처음 가보는 도시의 호텔 찾기
- **사용자:** 그 도시에 처음 가보는 일반 여행객
- **상황:** 여행 도시와 일정은 정해졌지만 어디에 묵을지 모름
- **목표:** 예산과 선호에 맞는 호텔을 빠르게 찾고 싶음
- **흐름:** 앱 실행 → 도시·일정·예산·선호 입력 → 추천 호텔 목록 확인 → 호텔 상세 확인
- **완료 조건:** 사용자가 조건에 맞는 호텔 목록과 핵심 정보(가격대·평점·위치)를 확인한다

### Scenario 2 — 추천 호텔 비교 후 예약하기
- **사용자:** 추천 목록을 받은 사용자
- **상황:** 여러 추천 호텔 중 하나를 고르려 함
- **목표:** 조건에 따라 비교하고 예약 사이트로 이동하고 싶음
- **흐름:** 추천 목록에서 정렬/필터 적용 → 호텔 상세 확인 → [예약하기] 선택 → 외부 예약 사이트로 이동
- **완료 조건:** 사용자가 선택한 호텔의 외부 예약 페이지로 이동한다

### Scenario 3 — 조건 바꿔 재검색
- **사용자:** 기존 이용자
- **상황:** 처음 추천받은 목록이 마음에 안 들어 조건을 바꾸고 싶음
- **목표:** 예산이나 선호를 수정해 다시 추천받고 싶음
- **흐름:** 검색 조건 화면으로 돌아가 예산/선호 수정 → 재검색 → 새 추천 목록 확인
- **완료 조건:** 수정된 조건이 반영된 새로운 추천 목록이 표시된다

## 6. Success Criteria
- SC-001: 신규 사용자가 도시·일정·예산·선호 입력을 마치고 추천 목록을 확인하기까지 2분 이내에 완료한다. (⚠️ 가설 — 실측 검증 필요, 오픈 이슈 참조)
- SC-002: 추천 목록에 표시된 호텔이 사용자가 입력한 예산 범위를 벗어나는 사례가 0건이다.
- SC-003: 추천 목록의 모든 호텔에 평점·리뷰 기반 정보가 함께 표시되는 비율이 100%다.

## 7. Edge Cases
- 해당 도시·조건에 맞는 호텔이 없는 경우: 조건을 완화한 대안을 제시하거나 결과 없음을 안내한다.
- 예산이 비현실적으로 낮아 매칭되는 호텔이 없는 경우: 예산 조정을 제안한다.
- 리뷰·평점 데이터가 부족한 신생/소규모 호텔: 데이터 부족을 명시하고 추천 우선순위에서 낮게 반영하거나 별도 표시한다.
- 필수 입력(도시, 일정)을 다 채우지 않고 추천을 요청하는 경우: 최소 필수 항목을 안내하고 진행을 막는다.
- 체크인 날짜가 과거이거나 체크아웃이 체크인보다 빠른 경우: 유효성 오류를 안내한다.
- 외부 예약 사이트 연결 실패/오류: 오류 상태와 재시도 또는 대체 링크를 안내한다.

- **v1 범위:** 도시·일정·예산·선호 입력(FR-001~004), 조건+리뷰 데이터 기반 추천(FR-005), 호텔 핵심 정보 확인(FR-006), 외부 예약 연결(FR-007)

## 11. Assumptions
- 호텔 데이터(가격, 위치, 편의시설)와 리뷰·평점 데이터는 외부 제공자(OTA API, 리뷰 플랫폼 등)로부터 가져온다고 가정한다. 구체적 데이터 소스·계약 방식은 미정.
- v1의 예약은 앱 내부에서 완결되지 않고, 외부 예약 사이트로 연결하는 딥링크/웹링크 방식이라고 가정한다.
- 추천 로직은 v1에서 입력 조건 필터링 + 평점 기반 정렬로 시작하며, 과거 검색·예약 이력 기반 개인화(AI 추천)는 v1 이후로 가정한다.
- 서비스 이름과 브랜드 톤은 아직 확정되지 않았으며, 별도 brand-voice·design-brandfit 단계에서 정해진다고 가정한다.
