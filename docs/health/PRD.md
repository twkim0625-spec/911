## 1. 개요
- **한 줄 정의:** 사용자가 겪고 있는 증상을 입력하면, 필요 시 추가 질문으로 상태를 확인한 뒤 자가관리로 충분한지 병원을 방문해야 하는지 preliminary(예비적) 제안을 주는 모바일 앱
- **해결하는 문제:** 몸에 이상 신호가 있을 때 이게 대수롭지 않은 일시적 증상인지, 병원에 가야 하는 상황인지 스스로 판단하기 어려워 불필요하게 불안해하거나 반대로 병원 방문을 미루는 문제
- **타깃 사용자:** 특이 질환 없는 일반 성인 (v1 기준 — 소아·임산부·기저질환자 등은 범위 밖, 12번 오픈 이슈 참조)
- **플랫폼:** 모바일 앱 (iOS + Android)

## 2. 배경 & 근거
- **시장/경쟁 맥락:** ⚠️ (benchmark.md 없음 — 추후 보완. benchmark-research 스킬로 닥터나우·굿닥 등 국내 서비스, Ada Health·Buoy Health 등 해외 증상 체커와의 비교가 필요하다.)
- **우리의 차별 프레이밍:** ⚠️ (benchmark.md 없음 — 추후 보완. 현재는 "검증된 트리아지 가이드라인 기반 규칙, 구체 약물명 없이 자가관리/병원방문만 구분"이라는 인터뷰상의 방향성만 있고, 구체적 차별점은 검증되지 않음.)

> ⚠️ **가장 중요한 전제:** 이 앱은 진단이나 처방을 제공하지 않으며, 응급 상황에서는 어떤 경우에도 추가 질문 없이 즉시 응급 안내를 최우선한다. 규제·안전 관련 세부 사항은 2번 하단과 12번 오픈 이슈를 반드시 확인할 것.

## 3. 목표 (Goals)
- 사용자가 겪는 증상이 자가관리로 충분한지, 병원을 방문해야 하는지 스스로 판단하는 부담을 덜어준다.
- 응급 위험 신호는 어떤 경우에도 놓치지 않고 즉시 올바른 행동(응급실 방문 등)으로 안내한다.
- 모든 제안이 "진단이 아닌 참고 정보"임을 명확히 해 오해로 인한 위해를 방지한다.

## 4. User Scenarios   ← 사용자 인터뷰
### Scenario 1 — 경미해 보이는 증상 확인하기
- **사용자:** 특이 질환 없는 일반 성인
- **상황:** 몸에 경미한 증상(예: 가벼운 두통, 미열 등)이 생김
- **목표:** 병원에 가야 할 정도인지, 그냥 쉬면 되는지 알고 싶음
- **흐름:** 앱 실행 → 증상 입력 → 응급 신호 없음 확인 → 추가 질문(지속 기간, 강도 등) 응답 → 자가관리/병원방문 제안 확인
- **완료 조건:** 사용자가 "자가관리 가능" 또는 "병원 방문 권장" 중 하나의 제안과 근거를 확인한다

### Scenario 2 — 응급 위험 신호 감지 시 즉시 안내
- **사용자:** 특이 질환 없는 일반 성인
- **상황:** 가슴 통증, 호흡곤란 등 응급 신호에 해당하는 증상을 입력함
- **목표:** (본인이 심각성을 인지하지 못했더라도) 즉시 올바른 조치를 안내받아야 함
- **흐름:** 증상 입력 → 시스템이 응급 신호 감지 → 추가 질문 없이 즉시 응급실 방문/응급 연락 안내 표시
- **완료 조건:** 사용자가 추가 질문 단계를 거치지 않고 응급 안내를 즉시 확인한다

### Scenario 3 — 증상 확인 중단 후 재시작
- **사용자:** 진행 중인 사용자
- **상황:** 질문에 답하던 중 증상이 바뀌거나 처음부터 다시 하고 싶어짐
- **목표:** 처음부터 다시 시작하고 싶음
- **흐름:** 진행 중 화면에서 [다시 시작] 선택 → 증상 입력 화면으로 복귀
- **완료 조건:** 이전 응답이 초기화되고 새로 증상을 입력할 수 있다

## 6. Success Criteria
- SC-001: 응급 위험 신호에 해당하는 증상 입력 시, 100%의 경우 추가 질문 없이 즉시 응급 안내가 표시된다. (핵심 안전 지표 — 타협 불가)
- SC-002: 모든 제안 화면에 "진단이 아닌 참고용" 면책 문구가 표시되는 비율이 100%다.
- SC-003: 신규 사용자가 증상 입력을 시작해 preliminary 제안을 받기까지 3분 이내에 완료한다. (⚠️ 가설 — 실측 필요)

## 7. Edge Cases
- 사용자가 여러 증상을 동시에 입력하는 경우: 모든 증상을 종합해 응급 신호 여부를 판단하고, 하나라도 응급 신호에 해당하면 그것을 우선해 즉시 응급 안내를 표시한다.
- 증상 입력이 모호해 트리아지 규칙에 명확히 매칭되지 않는 경우: 추측하지 않고 명확화 질문을 추가하거나, 매칭 불가 시 "판단 불가 — 병원/전문가 상담 권장"으로 안전하게 처리한다.
- 소아·임산부·기저질환자 등 v1 타깃 범위 밖의 사용자로 확인되는 경우: 이 앱의 범위 밖임을 안내하고 해당 전문 서비스나 병원 상담을 권장한다.
- 응답 도중 세션이 끊기거나 앱이 종료된 경우: 이미 응급 신호가 감지된 상태였다면 재실행 시 즉시 응급 안내부터 다시 표시한다.
- "자가관리 가능" 제안을 받은 뒤 증상이 악화된 경우: 재사용 시 새로 입력된 증상을 바탕으로 다시 판단하며, 악화 자체를 응급 신호 후보 항목으로 취급한다.
- 네트워크/서버 오류로 트리아지 판단을 받지 못하는 경우: 오류를 표시하고, 판단 불가 상황에서는 자가관리 쪽으로 기울지 않고 "병원/전문가 상담 권장" 방향의 안전한 기본 안내를 제공한다.

## 10. 범위 / 비범위 & 우선순위
- **v1 범위:** 증상 입력(FR-001), 응급 신호 최우선 판별 및 즉시 안내(FR-002~003), 트리아지 추가 질문(FR-004~005), 자가관리/병원방문 제안(FR-006), 면책 문구(FR-007), 자가관리 안내(FR-008)
- **Out of scope (지금 안 함):** 구체적 약물 성분·제품 추천, 병원 예약·약국 연계, 진단·처방 행위, 소아·임산부·기저질환자 대상 판단 로직. 다시 시작(FR-009)·진료과 안내(FR-010)·기록 조회(FR-011)는 v1 범위에 포함하되 첫 출시 최우선은 아님
- **우선순위 묶음(제품 관점):** MVP = FR-001~FR-008 (증상 입력 → 응급 판별 → 문진 → 제안 → 면책·자가관리 안내) / v1 = MVP + FR-009, FR-010 (재시작, 진료과 안내) / 이후 = FR-011 및 병원·약국 연계 등 확장 (단, 규제 검토 결과에 따라 확장 범위가 달라질 수 있음)
- *구현 마일스톤 로드맵은 vibe-build의 roadmap 스킬이 docs/health/ROADMAP.md에 작성한다.*

## 11. Assumptions
- 트리아지 규칙/체크리스트는 공인된 의료 가이드라인을 기반으로 의료 전문가의 검수를 거쳐 구축된다고 가정한다. 실제 콘텐츠 제작·감수 프로세스는 별도로 확보해야 한다(12번 참조).
- v1은 의약품 성분·제품을 추천하지 않으며, "자가관리 가능/불가능"이라는 큰 범주의 안내만 제공한다고 가정한다.
- v1의 판단 로직은 결정론적 규칙 기반이며, 자유 대화형 AI/LLM 기반 판단은 오탐·환각 리스크 때문에 이후 검토 대상으로 가정한다.
- 사용자가 입력하는 증상 정보는 민감한 건강정보로 취급되어야 한다고 가정한다 — 구체적 저장·처리 방식은 법무·보안 검토가 필요하다(12번 참조).
- 서비스 이름과 브랜드 톤은 아직 확정되지 않았으며, 별도 brand-voice·design-brandfit 단계에서 정해진다고 가정한다.

## 12. 오픈 이슈 / 리스크
- **⚠️ 규제 검토 필요 (최우선):** 증상을 입력받아 병원 방문 여부를 제안하는 서비스는 다수 국가에서 의료기기 소프트웨어(SaMD, Software as a Medical Device)로 분류되어 별도 인허가가 필요할 수 있다(예: 한국 식약처 의료기기 허가, 미국 FDA, EU MDR 등). 개발 착수 전 법무·규제 검토가 반드시 선행되어야 하며, 검토 결과(단순 정보 제공 서비스 vs 의료기기)에 따라 이 PRD의 기능 범위와 표현 방식이 달라질 수 있다.
- **⚠️ 트리아지 규칙 콘텐츠·감수 체계:** 의학적으로 검증된 트리아지 가이드라인을 누가(의료 자문단 구성 여부), 어떤 기준으로, 어떻게 지속적으로 감수·갱신할지 미정. 이는 서비스 안전성의 핵심이며 규제 검토와도 직결된다.
- **⚠️ 민감 건강정보 처리:** 증상·건강 데이터는 일반 개인정보보다 엄격한 보호(암호화, 접근 통제, 별도 동의 절차 등)가 필요할 수 있다 — 관련 법의 구체 요건 확인이 필요하다.
- 오탐(응급 신호를 놓침)과 과탐(불필요하게 응급 안내를 남발)의 균형 기준이 아직 없음 — 트리아지 규칙 설계의 핵심 트레이드오프.
- 제공된 안내를 따랐다가 문제가 생긴 경우의 책임 소재에 대한 법적 자문이 필요함.
- 경쟁 서비스(닥터나우, 굿닥, 해외 Ada Health·Buoy Health 등) 대비 차별화 포인트가 검증되지 않음 — benchmark-research 필요.
