## 1. 개요
- **한 줄 정의:** 평소 문화생활을 즐기는 사람들에게 좋아할 만한 영화·연극·음악·미술 등 공연·전시 정보를 추천하고, 예매가 열리기 전에 미리 알려준 뒤 예매까지 이어주는 모바일 앱
- **해결하는 문제:** 관심 있을 만한 공연·전시가 있어도 정보를 놓치거나 예매 오픈 시점을 몰라 좋은 좌석/티켓을 놓치는 문제
- **타깃 사용자:** 평소 문화생활(영화·공연·전시)을 즐기는 일반인
- **플랫폼:** 모바일 앱 (iOS + Android)

## 2. 배경 & 근거
- **시장/경쟁 맥락:** ⚠️ (benchmark.md 없음 — 추후 보완. benchmark-research 스킬로 인터파크·예스24 등 기존 예매처 앱, 공연 정보 큐레이션 서비스와의 비교가 필요하다.)
- **우리의 차별 프레이밍:** ⚠️ (benchmark.md 없음 — 추후 보완. 현재는 "선호 장르/아티스트 + 관람 이력 기반 개인화 추천과 예매 오픈 사전 알림"이라는 인터뷰상의 방향성만 있고, 구체적 차별점은 검증되지 않음.)

> ⚠️ **참고:** 실제 공연·전시 티켓의 좌석·재고는 대부분 기존 예매처(인터파크, 예스24 등)가 쥐고 있어, 이 앱은 v1에서 자체 예매를 완결하지 않고 외부 예매처로 연결하는 방식을 전제로 한다. 자세한 내용은 5·10·12번 참조.

## 3. 목표 (Goals)
- 사용자가 직접 찾아다니지 않아도 취향에 맞는 공연·전시 정보를 자연스럽게 접하게 한다.
- 관심 있는 공연·전시의 예매 오픈을 놓치지 않도록 사전에 알려준다.
- 발견부터 예매까지의 흐름을 끊김 없이 이어준다(외부 예매처 연결 포함).

## 4. User Scenarios   ← 사용자 인터뷰
### Scenario 1 — 취향 설정 후 맞춤 추천 받기
- **사용자:** 평소 문화생활을 즐기는 일반인
- **상황:** 앱을 처음 실행함
- **목표:** 나에게 맞는 공연·전시 정보를 받아보고 싶음
- **흐름:** 앱 실행 → 선호 장르(영화/연극/음악/미술 등)·관심 아티스트 설정 → 추천 목록 확인
- **완료 조건:** 사용자가 자신의 취향과 인기/신작이 섞인 추천 목록을 확인한다

### Scenario 2 — 관심 공연 찜하고 예매 오픈 알림받기
- **사용자:** 추천을 받은 사용자
- **상황:** 마음에 드는 공연·전시를 발견했지만 아직 예매가 열리지 않음
- **목표:** 예매 오픈을 놓치지 않고 싶음
- **흐름:** 공연·전시 상세에서 [찜하기] 선택 → 예매 오픈 전 알림 수신 → 알림 클릭 시 예매 정보 확인
- **완료 조건:** 사용자가 예매 오픈 시점 전후로 알림을 받는다

### Scenario 3 — 외부 예매처로 이동해 예매하기
- **사용자:** 알림을 받은 사용자
- **상황:** 관심 공연의 예매가 열림
- **목표:** 실제로 티켓을 예매하고 싶음
- **흐름:** 알림 또는 공연 상세에서 [예매하기] 선택 → 외부 예매처(인터파크·예스24 등)로 이동
- **완료 조건:** 사용자가 해당 공연·전시의 외부 예매 페이지로 이동한다

## 6. Success Criteria
- SC-001: 사용자가 찜한 공연·전시의 예매 오픈 알림이 설정된 시점 기준으로 빠짐없이(발송 성공률 100%) 발송된다. (⚠️ 실측·모니터링 체계 필요, 오픈 이슈 참조)
- SC-002: 신규 사용자가 선호 장르/아티스트 설정을 마치고 첫 추천 목록을 확인하기까지 2분 이내에 완료한다. (⚠️ 가설)
- SC-003: 추천 목록에 사용자가 설정한 선호 장르에 해당하는 항목이 절반 이상 포함된다. (⚠️ 구체 기준값은 가설, 실측 후 조정 필요)

## 7. Edge Cases
- 사용자가 선호 장르/아티스트를 하나도 설정하지 않은 경우: 인기·신작 중심 추천으로 대체 제공한다.
- 찜한 공연·전시의 예매 오픈일이 변경되거나 공연 자체가 취소된 경우: 변경/취소 사실을 알림으로 안내한다.
- 외부 예매처 링크가 만료되었거나 페이지 오류인 경우: 오류를 안내하고 예매처 홈 등 대체 경로를 제공한다.
- 이미 매진된 공연·전시를 추천하거나 알림을 보내야 하는 경우: 매진 상태를 명확히 표시한다(취소표 알림 등은 v1 범위 밖, 오픈 이슈 참조).
- 동일 공연이 여러 장소·회차로 열리는 경우: 회차별로 구분해 정보와 예매 오픈일을 제공한다.
- 공연·전시 정보 제공사의 데이터 오류/지연으로 잘못된 정보가 노출될 위험: 데이터 최신성을 표시하고, 오류 신고 경로를 제공한다.

## 10. 범위 / 비범위 & 우선순위
- **v1 범위:** 선호 설정(FR-001), 개인화+트렌드 추천(FR-002~004), 찜하기(FR-005), 예매 오픈 사전 알림(FR-006), 외부 예매처 연결(FR-007)
- **Out of scope (지금 안 함):** 앱 내부 좌석 선택·결제(자체 예매 완결), 취소표/대기 알림, 알림 시점 커스터마이즈(FR-008)·선호 수정(FR-009)·위치 필터(FR-010)·수동 관람 기록(FR-011)은 v1 이후로 미룰 수 있음
- **우선순위 묶음(제품 관점):** MVP = FR-001~FR-007 (취향 설정 → 추천 → 찜 → 예매 오픈 알림 → 외부 예매 연결) / v1 = MVP + FR-008, FR-009 (알림 커스터마이즈, 선호 수정) / 이후 = FR-010, FR-011 및 앱 내 예매 연동 확장
- *구현 마일스톤 로드맵은 vibe-build의 roadmap 스킬이 docs/culture/ROADMAP.md에 작성한다.*

## 11. Assumptions
- 공연·전시 정보(제목, 일정, 장소, 가격대, 예매 오픈일 등)는 외부 데이터 제공자(티켓 예매처 API, 공연 정보 플랫폼 등)로부터 가져온다고 가정한다. 장르(영화/연극/음악/미술)별로 서로 다른 소스가 필요할 수 있으며 구체적 소스는 미정.
- v1의 "과거 관람 이력"은 예매처의 실제 결제 데이터 연동이 아니라, 앱 내 찜·조회 등 활동 데이터를 기반으로 추정한다고 가정한다. 결제 이력 연동은 이후 검토.
- 예매는 v1에서 앱 내부에서 완결되지 않고, 외부 예매처로 연결하는 딥링크/웹링크 방식이라고 가정한다.
- 서비스 이름과 브랜드 톤은 아직 확정되지 않았으며, 별도 brand-voice·design-brandfit 단계에서 정해진다고 가정한다.

## 12. 오픈 이슈 / 리스크
- 공연·전시 정보 데이터 제공처(API 계약, 장르별 커버리지, 실시간성, 비용)가 정해지지 않음 — 영화·연극·음악·미술을 모두 아우르려면 여러 소스 연동이 필요할 수 있다.
- 예매 오픈 시각 정보를 정확하고 빠르게 확보하는 방법이 정해지지 않음(예매처마다 오픈 공지 방식이 다름) — 이는 FR-006(사전 알림)의 신뢰도에 직결되는 핵심 리스크다.
- 외부 예매처 연결 시 제휴 관계·수익 모델(제휴 수수료 등)이 미정.
- 경쟁 서비스(예매처 자체 앱, 기존 공연 정보 큐레이션 서비스) 대비 차별화 포인트가 검증되지 않음 — benchmark-research 필요.
- 상세 화면/온보딩 플로우(userflow)가 구체적으로 설계되지 않음 — userflow-generator 단계 권장.
- 서비스 이름·브랜드 보이스·시각 디자인 시스템 전부 미정.
- SC-001~003의 목표 수치는 실측 없는 가설이다.
